Boot & Desktop Runtime

Boot-stage map, display-server integration, terminal/shell providers, command and ISA coverage, and evidence-based release gates.

Native Koronos production ISO: not yet accepted

Boot sequence

BIOS/UEFI → Spit Fire → Jasper (or GRUB2 Multiboot2 fallback) → Koronos → CPIO initramfs/VFS → validated ring-3 target ELF → live, installer or recovery target.

The phase ordering is referenced against modern Linux (kernel, initramfs, PID 1/systemd, services, display manager/session, X.Org or Wayland compositor) and Windows (Boot Manager, OS Loader, kernel, Session Manager, Winlogon/services, desktop). These are architectural references, not claims of Linux or Windows ABI compatibility.

Jasper, Gates, Spit Fire and GRUB2 are configured for a 300-second interactive wait before choosing the default item.

Koronos native runtime

Incomplete x86-64 is the current kernel build/boot target. The live ring-3 payload is an interactive built-in console, not a general shell or desktop. Kore PID 1/service startup and a native display server are not yet integrated into this path.

Installer & recovery

Incomplete Installer currently reports a dry-run storage plan and does not write disks. Recovery currently reports diagnostics and does not repair filesystems or restore installations. A real block-device/VFS transaction and rollback backend is still required.

Architecture status

x86-64 kernel build and QEMU boot path. AArch64 and RV64 early entry/UART probes only; not full kernel ports. x86-32 serial probe only.

X server and desktop sessions

The hosted Chimera II OS and OctavianOS desktop images use a Linux kernel and package the real distribution X.Org X Server, Xwayland, xinit/startx, input/video drivers and an XDG session dispatcher. This is a working hosted-Linux display-server path; it is not a native Koronos X server.

chimera-xserver-session list enumerates installed X11 sessions. chimera-xserver-session start SESSION_ID starts an installed session only if its real executable exists. Wayland sessions remain managed by their own compositor and are not launched inside X.Org.

Open-source terminals and shells

Aurora registries contain 20 terminal-emulator entries and 8 shell entries. Both hosted editions use the same package-first/source-build fallback pipeline. The build records provider path, ELF machine or script interpreter, source revision and binary hash; shell command smoke tests and terminal version probes gate launcher creation. Missing providers are not replaced by empty files or fake executables.

Launchers are generated only for providers that are actually present and pass the configured checks. These providers run in hosted Linux userspace and do not prove Koronos syscall compatibility.

Commands and ISA

Command catalogue

Latest branch inventory describes 971 catalogue entries, including 90 Chimera-native command entries. The prior audit identified 838 entries without genuine implementations or verified provider binaries; the final target-rootfs report must recompute that number after the complete build.

Native/hosted distinction

The shared POSIX multicall currently implements 38 aliases and is cross-built for eight Linux userspace ABIs, with native/QEMU-user smoke tests. These are Linux ELF providers, not Koronos-native command binaries. Koronos-native command execution remains a release gate.

ISA

ISA catalogues, architecture metadata and encoding samples are packaged. Catalogue rows and encoding samples do not count as instruction semantics. Each claimed ISA backend still needs decoder/encoder/lowering semantics and conformance tests.

Aurora artwork & sound

Hosted editions package the generated boot/desktop/installer/recovery/diagnostics/live/mobile artwork, the original 133-icon application-artwork catalogue and exported scalable icon assets, wallpapers and audio event/startup files. This asset pipeline is separate from native Koronos graphics support.

Release gates

  • Writable VFS, block-device API, partition/filesystem drivers, safe installation transaction and rollback.
  • Native PID 1, process lifecycle, executable/script loading and Kore service dependency management.
  • DRM/KMS, display/input/audio/network drivers, and a native Koronos X server or Wayland compositor.
  • Native Aurora and other desktop sessions launched from the Koronos boot target.
  • Full AArch64 and RV64 kernel ports with interrupt, memory, scheduler, syscall and QEMU/device acceptance.
  • Genuine implementations or verified providers for every command entry, plus semantic ISA and conformance coverage.
  • One immutable ISO per edition/architecture with SHA-256, boot report, installer/recovery runtime tests and successful CI.

A hosted Linux live ISO is not labelled a Koronos-native production release. No release is accepted merely because an image builds or a catalogue entry exists.
