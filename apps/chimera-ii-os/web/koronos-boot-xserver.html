From firmware to Aurora.

A Linux-style staged boot design for Spit Fire, Jasper, GRUB2, Koronos, initramfs, Kore services and Aurora—with explicit boundaries between hosted Linux functionality and the freestanding native kernel.

Boot sequence

Firmware
BIOS/UEFI, CPU and platform data.
Spit Fire
Architecture bootstrap and handoff.
Jasper / Gates / GRUB2
Visible menu; waits 300 seconds before default.
Koronos entry
Validates CHMBOOT1 and Multiboot2 modules.
Memory and address spaces
Frame allocator, page tables and ring-3 entry checks.
Initramfs VFS
Validates CPIO newc and required root files.
Drivers and scheduler
Discovers devices, probes drivers and schedules tasks.
Userspace and Kore
Admits selected live, installer or recovery ELF.
Display and session
Hosted Linux X.Org/Wayland then Aurora; native Koronos remains gated.
Native Koronos limitation

The current CPIO VFS is read-only and the kernel does not yet execute shell-script /init directly from that archive or perform a generic switch-root. The selected ring-3 target ELF is a separate Multiboot2 module. The installer remains dry-run; native X.Org/Wayland and a production Aurora desktop are not complete. Koronos is currently x86-64-only.

X.Org server for hosted editions

Both hosted Linux desktop editions include X.Org, Xwayland and an XDG session dispatcher. It launches only desktop sessions whose .desktop entry and executable are actually installed.

chimera-xserver-session list — discover installed X11 sessions.

chimera-xserver-session start chimera-aurora-x11 — launch the Aurora X11 fallback through X.Org.

The Aurora X11 fallback uses Openbox and the WebKit kiosk. Wayland sessions stay with their compositor; Xwayland handles X11 applications inside Wayland.

Command and ISA coverage

Catalogues are shipped as reference data, with actual provider binaries and instruction backends audited separately. The native command multicall is a subset, not the whole catalogue. Unsupported commands and ISA instructions remain explicit gaps; no placeholder executables are generated.
