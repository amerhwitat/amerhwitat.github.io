Octavian QEMU ISA-baseline diagnosis — 24 November 2026

The diagnostic-only QEMU trace from OctavianOS kernel run 45334940252 captured an invalid-opcode exception (#UD) at RIP 0x10db10. The matching ELF symbol/disassembly identifies this as the BMI2 SHRX instruction inside frame_trace_hex64; the same kernel ELF contains additional SHRX/SHLX instructions in allocator bit helpers. The exception then escalated to #GP with error code 0x0032 and a triple fault. This established an instruction-set baseline mismatch in the built kernel, not a malformed second Multiboot memory range.

The corrective build changes on OctavianOS PR #236 set kernel/build-koronos.sh and kernel/Makefile to the generic x86-64 baseline (-march=x86-64 -mtune=generic -mno-bmi -mno-bmi2 -mno-avx -mno-avx2) and pin the smoke VM to -cpu qemu64. Kernel QEMU smoke run 45335387268 succeeded: both usable memory ranges were parsed, frame allocator initialization completed, and [KRN ] KORONOS READY was reached with no #UD/triple fault. The exact kernel ELF artifact was disassembled and contained none of the checked BMI1/BMI2 mnemonics. The trace still reports one online CPU.

The candidate ring-3 handoff subgate (not the production release matrix) initially failed 0/6 in 45335387295 because the target init probes omitted the explicit syscall-return marker. PR #236 added a second user-originated write after the readiness syscall returns. The rerun 45336024532 now passes 6/6 across Live/Installer/Recovery × BIOS/UEFI. All six logs contain a ring-3 USERSPACE READY marker with a consistent nonzero PID, the USERSPACE SYSCALL RETURNED TO RING3 marker, and the candidate launch-smoke pass message. This proves the tested init probes entered ring 3 and returned from a syscall; it does not prove a persistent PID 1 or complete production userspace.
