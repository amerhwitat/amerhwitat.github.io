Production acceptance gates

These gates are intentionally independent of static checks, browser artwork, kernel probes, and workflow queue state.

  • All six real boot cases: Live, Installer, Recovery × BIOS and UEFI.
  • Each production trace proves kernel readiness, a user-originated syscall acknowledgement, and target readiness from the real production init/session path.
  • Native desktop/session and application launch with observable display/runtime health.
  • Installer writes to the target disk and the installed system retains state after a cold reboot.
  • Recovery repair verifies its actual postcondition, not just a successful command return.
  • Measured overlapping execution on at least two CPUs; CPU-online messages or sequential traces are not SMP proof.

Release rule: any missing, stale, synthetic, or failed evidence keeps the corresponding OS release blocked.
