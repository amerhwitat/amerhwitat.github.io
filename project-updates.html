Acceptance limits and release gate

The intended boot path remains Spit Fire → Jasper/GRUB → Koronos ELF → hardware/driver initialization → scheduler/runtime loop → live/recovery/installer userspace → Aurora. Current CI evidence must be read at the exact level tested.

  • PR #129's QEMU check is a kernel-entry smoke test, not interactive GRUB validation or production userspace acceptance. Installer disk operations are disabled until a real installation backend is configured.
  • The Live handoff diagnostic PR explicitly acknowledges that the production launch adapter is not yet wired for every path.
  • The last reviewed OctavianOS full-ISO QEMU candidate timed out without the expected debug-console trace. Keep it as a review artifact until full-ISO boot validation passes.
  • Do not infer userspace-ready from kernel-ready; cataloged ISA entries do not imply executable/conformant instructions; sequential multi-CPU simulation does not prove genuine SMP.
  • Draft/open PRs remain review work. No new production release is claimed by this portfolio update.
