ISA catalog refresh and semantic metadata

The online ISA discovery/refresh work is available for review, but the current PR checks have not passed all build gates. It is not represented as a completed, production-wide ISA execution backend.

  • ChimeraIIOS PR #102 — online ISA refresh and semantic metadata: the Docker ISO failure was traced to a missing busybox dependency in the builder image. Fix committed on the PR branch as e407b813; rerun checks are in progress.
  • OctavianOS PR #41 — ISA refresh pipeline integration: kernel smoke checks pass, but the full BIOS ISO QEMU run produced no Koronos debug trace; full-ISO boot acceptance remains blocked and unverified.
  • The --refresh-isa-catalog alias fix is committed to ChimeraIIOS development branch koronos/elf-smp-acceptance-gate; it is not yet the same as a merge to main.

Catalog discovery and register/operand metadata are not proof that every instruction is implemented, that every compatibility backend executes correctly, or that an ISO has booted successfully.

Boot UI and validation boundary

The source work targets the boot chain Spit Fire → Jasper/GRUB → Koronos ELF → hardware/driver initialization → scheduler/runtime loop → live/recovery/installer userspace → Aurora, with high-resolution menu modes, fallback display modes and visible progress/log events.

Those source changes are published here as status and source links. Complete BIOS/UEFI QEMU coverage, highest-resolution selection/fallback validation, each menu handoff, actual installer/recovery userspace readiness, and boot-to-Aurora acceptance remain separate verification gates until their runs report success.
