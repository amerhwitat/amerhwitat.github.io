Production userspace failure root cause — 19 October 2026

Fresh source/log audit confirms that the six failures are not caused by the build or ISO packaging gate. The final unchanged verifier in OctavianOS run #39209603140 rejected all six fresh BIOS/UEFI traces with missing user-originated init syscall acknowledgement (CPL 3), actual init PID readiness marker. ChimeraIIOS run #39207743325 likewise failed its final gate after kernel build, ISO validation, QEMU kernel smoke and artifact upload succeeded.

Source mismatch confirmed: boot currently stages shell-based initramfs payloads, while the native launcher requires exactly one CHIMERA_MODULE_USER_INIT_ELF module with a target-specific command line. The mainline bootstrap tasks explicitly state that the initramfs is registered but no executable ring-3 path is connected. Therefore no actual production init reaches the syscall/readiness handshake. The kernel's generic compatibility syscall dispatcher also has no process context; the fail-closed candidate correctly rejects fabricated GETPID/EXIT success, but it does not supply the missing process lifecycle.

Do not stage a test/probe ELF as production init, synthesize readiness markers, or weaken tests/migration/verify-userspace-handoff.py. Required next implementation: native target-aware PID 1/KSO or a genuinely supported initramfs interpreter; process-owned address spaces and CR3 switching/cleanup; GDT/TSS/RSP0 and CPL3 entry/return; caller-bound PID/exit/wait/reap and required filesystem calls; then six separate unchanged-verifier passes. Live→Aurora, installer completion/reboot, real Recovery, and AP-backed concurrent SMP must pass independently. Release remains blocked.
