VoiceConnect: architecture and capabilities

VoiceConnect is an experimental browser and desktop voice/video application built around WebRTC. It is designed for small groups that need a shared room for live media and text communication.

How a meeting works

A participant chooses a nickname and room name, grants the device permissions they intend to use, and joins. The signaling service introduces participants in the same room. Clients then negotiate peer-to-peer WebRTC connections for media and data.

The current room design uses a full mesh with a maximum of eight participants. Each client connects to the others. This is useful for small demonstrations, but it is not an SFU architecture; bandwidth and CPU requirements rise as participants are added.

Included capabilities

  • Room-based participant discovery and peer introduction.
  • WebRTC audio/video, device selection, preview, mute and camera toggle.
  • Nicknames, locally selected avatars, UTF-8 chat and emoji.
  • Optional screen sharing, subject to explicit operating-system/browser permission.
  • STUN/TURN configuration and short-lived TURN credential support when configured by the server operator.
  • Windows, Linux and macOS Electron packaging workflows.
  • Java, Python and C++ companion chat clients; these are not native WebRTC media clients.

Architecture boundaries

Room names are selectors, not authentication. Public use requires authenticated identity or room-scoped invitations, strict origin controls, rate limiting, abuse handling, TLS/WSS, secure TURN operations and ongoing monitoring. The full-mesh topology is not suitable for large meetings; a separately deployed SFU is needed for that scale.

The project does not claim to include a built-in VPN, global peer discovery, offline messaging, resumable transfers or independently certified end-to-end encryption.

Development and release status

Automated package builds and source tests are not substitutes for testing the application on real devices. The Windows GUI click-through check exercises trusted mouse input against a packaged Electron app; physical-device acceptance and independent security review remain separate requirements. Preview packages must not be confused with signed production releases.
