Installing and troubleshooting VoiceConnect on Windows

This guide covers the Windows Electron application. It does not imply that a particular package is signed or production-certified.

Build from source

Install Node.js 20 or newer, then run these commands from PowerShell or Command Prompt:

cd voiceconnect-p2p
npm ci
npm test
npm run build:win

Windows CI also builds Direct3D 11 and OpenGL variants and runs package/install/startup checks. Build outputs are written to dist\.

First launch and device permissions

  1. Launch VoiceConnect and choose a nickname.
  2. Join a room using the name shared with the other participants.
  3. Select the intended microphone and camera.
  4. Grant camera or microphone access only when you intend to use those devices.
  5. Use the mute and camera controls to stop sending the corresponding media track.
  6. Start screen sharing only when needed, select the intended display/window, and stop sharing when finished.

Windows privacy settings may also block device access. If a device is unavailable, review Windows Settings → Privacy & security → Camera or Microphone. Denying permission is a valid choice.

If a button does not respond

  1. Check that no dialog or invisible overlay covers the control.
  2. Resize or maximize the window and retry.
  3. Check whether the control is disabled because a prerequisite is missing.
  4. Restart the app and retry before joining a room.
  5. Record the app version/commit, the control, the visible state and exact reproduction steps.

The project adds a Windows GUI test using Chromium's mouse-input dispatch to check hit-testing and event-handler delivery. Automated success does not replace testing different display scales, assistive technologies, device drivers and physical hardware.

Connectivity

Signaling introduces participants; WebRTC ICE establishes media paths. Firewalls and NAT may require a properly configured TURN service. The desktop HTTP proxy settings do not automatically tunnel WebRTC UDP media. Test with two physical devices on distinct networks and verify signaling, ICE path selection, two-way media and screen sharing.

Download safety

Use only artifacts linked from official GitHub Actions runs or GitHub Releases. CI artifacts may require repository access and expire according to retention policy. Unsigned preview builds can trigger SmartScreen or publisher warnings. Verify origin and checksum before running them; a production Windows release must pass the Authenticode signature gate.
